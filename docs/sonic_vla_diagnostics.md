# 官方 VLA 动作头的仿真迁移排查

后续新增的夹持保持反馈与重复验收见 [冻结 VLA 抓取保持](sonic_vla_stable.md)。本文保留未加该反馈的原始动作头对照结果。

本轮遵照用户要求保持官方权重不变，不进行微调。使用 `UnifoLM-WLA-1.0-Base` 的原始 `get_action` 动作头，输入只有三路 RGB、测得的机器人状态和指令。运行时不调用 `ground_object`，不读取 RGB-D、物体位置或示范未来动作来生成控制目标。桌面布局供场景生成与独立评分器使用。

权重 SHA256：`65ac8911ce5556631cb538fb4d3499d9131d95b1da4eb1ce970c4215997d3299`。官方录制数据仅用于工具/准备姿势校准和离线接口检查，没有训练或替换 checkpoint。

## 本轮结果：尚未通过持续保持验收

2026-10-27，在 `pi0.5` 完成多轮冻结权重对照。没有一轮达到原定的“方块最低点离桌至少 8 cm、指定手双指连续承重至少 2 秒”的完整条件，未降低验收标准。

最佳一轮的峰值确有两个不同夹指的接触力，物体无桌面支撑、无吊带，其他方块没有被抬起。它证明原始动作头已能产生真实的短暂抓取，但不能称为稳定完成抓取保持。`raw-vla-016-pd` 的相对手内物体位置几乎不变，手与物体同步下降，随后松爪，支持“策略继续执行放回”而非单纯滑脱的判断。复测与长保持指令均未稳定重现通过条件。

测量汇总在服务器 `artifacts/grasp/raw-vla-validation.json`，本机在 `results/sonic/grasp/vla-diagnostics/validation.json`；最佳一轮的完整视频、原始回复和物理轨迹在同目录的 `raw-vla-017-pd/`。`grasp-and-return.mp4` 仅截取原视频的连续帧、保留原帧率，完整视频仍保留。回归测试 102 项通过。试验结束后停止本任务的模型、控制器和仿真进程，保留环境、权重和证据。

## 已定位的问题

1. **动作段后半段被重规划覆盖。** 模型输出 30 帧、30 Hz 的一秒动作段，旧执行器约每 0.6–0.8 秒接纳一个新段。模型给出的后半段下降动作可能持续得不到执行。新增 `execute_full_chunk`，执行完整参考段后再请求下一次推理；针对“只有最后五帧包含运动”的真实回环网络测试可复现并防止该问题。`align_first_ee_frame` 关闭，保留服务器已组合好的绝对末端纠偏量。
2. **仿真图像会改变动作头的判断。** 固定初始状态、交换实拍和仿真图像时，初版画面的左臂一秒末端预测由实拍输入的下降约 29 mm 变成上抬约 41 mm。交换状态的影响较小。校准场景/视角后，两个方向分别约下降 26/28 mm。每组仅两次随机推理，这些数值用于定位问题，不是统计意义上的性能评估。
3. **腕部图像影响夹爪时机。** 校准后的固定状态测试中，完整实拍图像预测初始夹爪约 4.50；完整仿真约 3.75。保留仿真头部、换入实拍双腕时恢复为约 4.49。单独换入实拍头部仍约 3.83，提示剩余的提前闭合主要与腕部画面有关。
4. **准备姿势和夹爪替身不匹配。** 旧准备动作只对齐双手末端，没有对齐记录中腰部约 0.136 rad 的前倾。新增 `ready_waist`，与工具偏移一起按观测校准。VLA 专用场景单独设置相机、光照、夹指位置与颜色，不改此前两色块混合控制验收的默认场景。
5. **机械开度与模型反馈需要一起校准。** [官方 Dex1 URDF](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/dexterous_hand_description/dex1_1/dex1_1.urdf) 的滑动夹指几何与限位给出约 1–90 mm 的开度；在电机位置线性映射假设下，记录中的约 2.43 对应约 40 mm。因此以 4 cm 方块和相应的替身闭合端点作独立对照。该尺寸是几何推算与记录对照，不能作为实机夹爪标定结论。
6. **SONIC 神经上身跟踪的厘米级偏差影响抓取。** 接触附近曾出现约 3–7 cm 的目标/实测末端差异。IK 按预测腰角计算，而实测腰部可能不同，两臂因此出现共同偏差。外层积分补偿实验反而导致较大运动和停止，默认关闭；不能把它称为有效修复。

## 已检查但未证实为主因的候选

当前 `QwenMMDiT.forward` 在无 assistant 解答时使用聊天模板的默认 generation prompt，而 `predict_action` 显式关闭它。增加了默认行为不变的诊断开关，与固定扩散噪声种子一起做配对测试，没有改变参数权重。

三个实拍时刻、三个种子的 A/B 中，开启 header 后左右末端 RMS 没有一致改善；仿真初始观测的一秒末端差异约为毫米量级，夹爪判断基本不变。因此保留原推理默认值 `False`，不把这个代码差异认定为抓取失败根因。相同种子下，默认设置与显式 `False` 的回复最大绝对差为 0，结果在 `prompt-ablation.json` 与 `prompt-repeatability.json`。

## 执行方式与验证边界

保留两种可对照的执行方式：

- `--arm-tracking sonic`：官方 SONIC 神经策略执行全部身体关节。
- `--arm-tracking joint_pd`：**仿真对照驱动**，双臂和腰部使用模型/IK 给出的关节位置、原生电机 PD 增益及机器人重力补偿；12 个腿关节仍由 SONIC 平衡。夹爪仍执行原始 VLA 输出。这不是 SONIC 神经策略完成上身跟踪的证据，也没有完成实机驱动部署。

位置伺服仅订阅同一原生 planner 关节参考，不读取目标方块、深度、接触或评分结果；力矩仍受上游电机限幅。物体是自由刚体，没有焊接、附着或直接位置控制。

`action_time_scale: 2.0` 对整段预测的手臂与夹爪时间轴统一伸缩；不改变目标位置，不插入抓取阶段或物体相关的动作。这样可减少墙钟快于物理仿真、以及上身跟踪延迟的影响。该参数和完整段执行均在每轮解析后配置中保存。

## 复现

按 [基础部署](sonic_simulation.md) 启动同一官方权重的模型服务后，在 `pi0.5:/mlplatform/jy/unifolm-sonic/src` 执行：

```bash
../venv-sim/bin/python -m robot_client.sonic.grasp_trial \
  --workspace .. --simulation --policy vla --arm-tracking joint_pd \
  --task robot_client/sonic/tabletop_vla.yaml \
  --config robot_client/sonic/vla_grasp.yaml --seconds 100 \
  --output ../artifacts/grasp/my-raw-vla-trial
```

更换为 `--arm-tracking sonic` 可比较神经上身跟踪。每轮必须使用新输出目录；控制器、仿真及本轮进程自动清理，模型服务单独管理。原始 VLA 路径不启动 RGB-D 发布器。

原始动作头的末端、夹爪和腰部均来自 `get_action`；planner 模式仍由 SONIC 生成腿部参考。原始回复在 `actions/reply-*.npz`，实际模型图像在 `actions/obs-*.jpg`，发送/测量跟踪在 `control.jsonl`，真实物体接触在独立 `physics.jsonl`，最终物理评分在 `task-report.json`。客户端 `passed` 仅代表控制序列正常结束，不能代替物理任务评分。

新诊断配置保存每次请求的无损 PNG 与精确状态，较早试验保存间隔 JPEG。`--time-scale`、`--instruction`、`--inference-seed` 可作显式对照；固定种子只复用推理噪声，不等于训练或替换动作。默认上身执行方式仍为 `sonic`，位置伺服必须显式选择。

当前证据支持先解决相机/夹爪标定与精确上身跟踪，再检验策略在仿真中持续保持的行为；它不能证明冻结权重绝对无法成功，也不能当作未见场景上的泛化成功率。

## 离线检查

`diagnose_vla.py` 用同一状态交换实拍、仿真、混合头/腕图像；`evaluate_recording.py` 在公开录制的 8 个时刻使用真实观测，与未来动作标签作离线比较。后者完全不控制机器人，未来标签不会进入模型观测。

本次实拍观测检查的左右末端位置 RMS 均值约为 11.32/7.34 mm，夹爪 MAE 均值约 0.034/0.0067。它支持归一化、坐标组合与输入接口基本一致的判断；它不是闭环抓取成功率，也不能证明这些公开数据不在模型训练集中。

服务器证据：`artifacts/grasp/vla-probes-001`、`vla-probes-002`、`vla-real-replay` 和 `raw-vla-*`。较早失败的试验及其原始配置均保留，不从试验历史中删除。
